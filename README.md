# Warframe Economist

> Home page (`/`): hero, today's best moves from live data (set flips, top and rising arcanes, priciest parts) and, signed in, a snapshot of your saved inventory. The Market page (Warframe Market account + riven listings) is reached from the Inventory page header.

The all-in-one Warframe platinum tool: price and grade rivens, arcanes and Prime parts, track your inventory (including from screenshots), and list and manage your Warframe Market orders. Next.js (App Router, TS, Tailwind) + Supabase, deployable to Vercel. One responsive codebase: bottom tabs on phones, sidebar on desktop.

> **Unofficial.** Warframe Economist is a fan-made tool. It is not affiliated with, endorsed by or sponsored by Digital Extremes. Warframe and all related names, marks and imagery are trademarks of Digital Extremes Ltd.

## Accounts are optional

- **No account:** check a riven (per-stat grades + market estimate — it lives in the URL, nothing is stored) and browse arcanes with live prices.
- **With an account:** save and edit rivens, and list them on Warframe Market.
- **Screenshot scan is open to everyone** but rate limited (6 per 10 min per visitor, `SCAN_DAILY_LIMIT` per day per server instance, in-memory so best-effort). Set a monthly spend limit on your Anthropic key for a hard ceiling.
- Game reference tables (weapons, stats, riven grading data, arcanes) are publicly readable (migration 0007); user data and token tables are not.
- The public market endpoint (`/api/market/riven`) uses the same throttle + cache as everything else, but it is open to anyone — add rate limiting before sharing the URL widely.

## Setup

1. `npm install`
2. Create a Supabase project, run `supabase/migrations/0001…0015` in order (SQL editor or `supabase db push`).
3. `cp .env.example .env.local` and fill it in (Supabase URL/keys; `WFM_TOKEN_ENCRYPTION_KEY` via `openssl rand -base64 32`; optional `ANTHROPIC_API_KEY` for screenshot scanning).
4. Load reference data (re-runnable any time):
   ```bash
   npm run sync:wfm-static          # weapons (+disposition) and riven stat definitions, from Warframe Market
   npm run sync:wiki-arcanes        # arcanes, drop sources, compatibility, Vosfor collections, from the Warframe Wiki (+ WFM ids)
   npm run sync:arcane-prices       # rank-0 market prices + 48h sales for every arcane (the app also keeps these fresh by itself)
   npm run sync:primes              # data/primes.json: every Prime part/set and Lith–Axi relic (drops, vaulted) — commit the result
   npm run sync:item-prices         # Prime part/set prices (the app also keeps these fresh by itself)
   ```
   `-- --dry-run` on the sync scripts writes JSON to `data/generated/` instead of touching the DB.
5. `npm run dev`

## Things worth knowing

- **Riven auctions are v1-only.** Warframe Market v2 has no riven auction endpoint, so pricing and listing use `/v1/auctions/*`; everything else uses v2. Closing a listing is `PUT …/close` (DELETE returns 405).
- **Pricing:** `src/lib/wfm/valuation.ts` turns the comparable listings into a range: each ask is adjusted for how its roll quality (from the per-stat grades, curse rating included) compares with yours, troll and mispriced asks are dropped statistically (log-price median ± 3 robust deviations), exact-stat, fresher, closer-valued, in-game listings weigh more, and each seller counts once. The result is the weighted 25th/50th/75th percentile plus a confidence label. Every constant is in `VALUATION`. The roll-quality elasticity (0.7: best roll ≈ 2× the worst) is a prior, not a fit — public asking prices cluster at round defaults, so it can't be measured from them. Asks are not sales; real sale prices are usually lower.
- **Vault worth:** My Rivens shows each riven's last estimate (stored on the row, migration 0011), re-prices stale ones one at a time in the background, and totals them. Editing a riven clears its estimate.
- **Asking-price recovery after Baro leaves** is NOT shown as a number: completed-trade records barely react to his visits (the daily low moves less than on an ordinary day), so a recovery time measured from them was an artifact. The asking price (what actually falls) is saved hourly for his items instead and charted on the away view; a real recovery time can come from that once a visit or two is recorded.
- **While Baro is away** the tab follows the items from his last visit (`src/lib/baro/tracking.ts`): price versus while he was here and versus its usual price, units sold per day, a chart from the week before he came to today, and an hourly-tracked asking price (kept by `/api/baro/refresh` into `price_history`).
- **Sales tracker (`/inventory/sales`):** platinum earned per week/30 days/all time, a per-week chart and a log. Sales can be added by hand, or detected: each time the user opens My listings (or presses "Check my orders now") `/api/sales/sync` compares their current Warframe Market sell orders with the last look (`order_snapshots`); an order that disappeared or shrank becomes a PENDING sale to confirm (it could be a removal — orders removed through the site are not flagged). Confirmed sales only count. It can't see an order that was listed and sold between two looks (migration 0021; logic in `src/lib/sales/detect.ts`).
- **Varzia (own nav tab, `/varzia`):** her Prime Resurgence stock from the world-state feed; Prime sets / weapons are mapped to Warframe Market sets (`src/lib/varzia/map.ts`), shown with their cost in Regal Aya (and Aya), plat per Regal Aya, and how the set's price moved since the rotation began versus the week before (records only, nothing projected).
- **Baro Ki'Teer (own nav tab, `/baro`; the Live page just links to it):** per-item detail with a visit-by-visit table and a 90-day chart with his visits shaded, a budget planner (best combination for the ducats/credits you have, `src/lib/baro/basket.ts`), and the picks: while Baro is here, his stock (credits + ducats), each tradable item's live price, its usual price in the week before he arrived, and a records-only read on how past visits' prices came back (90-day sales history, visits every 14 days; `src/lib/baro/analysis.ts`). Estimates are capped at the usual price (past ratios above 1 are mostly market trend), only shown with 4+ visits of records, and 'Buy & hold' needs the price back to usual in 60%+ of them; the hit counts are shown. Blueprints are never matched to the tradable item. One horizon (2–4 weeks after he leaves — a short-term horizon came out identical, so it was removed) and a sort (expected price, platinum per 100 ducats, or gain). Recommended pickups = the top items whose projection beats today's price by 5%+, with plain-English tips and a confidence level (the pattern can't prove Baro sold the item on earlier visits, so it also reports how consistently the price dipped). Filled by `/api/baro/refresh` (migration 0020).
- **Set flips (`/primes/flips`):** sets that sell for more than their parts cost to buy (`src/lib/primes/flips.ts`), sorted by profit or return; asking prices, thin markets can be hidden.
- **Ducat advisor:** a part is flagged "better as ducats" at 10+ ducats per platinum (`src/lib/primes/ducats.ts`); the scanner also splits your parts into sell-for-plat vs take-to-Baro.
- **Price history & charts:** every arcane page (`/arcanes/<slug>`) and Prime part page (`/primes/<slug>`, click a name in the list) has an interactive 90-day chart (hover/tap for a day, click to pin, 7/30/90d, toggles). It combines (a) Warframe Market's real closed trades — daily average / low–high / units sold, copied into `sales_history` by `/api/history/refresh` (migration 0018) — and (b) our own daily asking-price snapshots in `price_history` (0017). Arcane cards and Prime rows show a 90-day sparkline (weekly average price paid) and the move from ~30 days ago to the last week, from the `price_trends()` SQL function (migration 0019); arcanes can be sorted by rising/falling fastest.
- **Keeping it fresh without visitors:** a Supabase `pg_cron` job calls the public refresh endpoints (`/api/arcanes|primes|weapons/prices/refresh`, `/api/history/refresh`) on the production URL every minute, each doing a small batch of whatever is stalest. Prices are only counted from online / in-game sellers (nobody buys from an offline seller when they need something now), so they're checked often: valuable arcanes (10p+) and Prime parts (15p+) every ~15 minutes, the long tail about hourly; sales history daily.
- **Inventory tab (`/inventory`: scanning works for Prime parts and for arcanes — arcane tiles keep their rank, tracked as unranked or max rank — Prime parts & arcanes, `/inventory/scan` screenshots, `/inventory/rivens` your rivens; the old /market/inventory, /primes/scan and /rivens redirect). Scan screenshots (inventory screens, or mission-reward screens in "Mission rewards" mode where each screenshot is summed and saving resets the page):** attach screenshots of your Prime parts (up to 12). Each is sent to Claude vision (`src/lib/primes/scan-read.ts`, needs `ANTHROPIC_API_KEY`, rate limited), the names are matched to the Prime catalogue (`scan-match.ts`: exact, else a close match that is clearly better than the runner-up, else listed as unmatched), items seen in overlapping screenshots are counted once (largest quantity), and everything is valued at the 5-cheapest-listings price, most expensive first. Counts are editable; signed-in users can add the result to their inventory. **List on Warframe Market** (complete Prime sets are combined into a set order when the set sells for more than its parts — `src/lib/primes/combine-sets.ts`; Prime parts, arcanes at rank 0/max rank via `/api/market/list`, and rivens via `/api/rivens/[id]/push`; every item has its own List button and there is a bulk "list everything" with a pricing rule and a minimum price): signed-in users who connect their WFM account get a price screen — each part shows the 5 cheapest listings from online / in-game players (`/api/primes/listings`, `src/lib/wfm/listings.ts`) to click as a price — or "Auto-price & list everything" (market average of the 5 cheapest, undercut by 1, or match the cheapest). Orders are posted by `/api/primes/list` (v1 `POST /v1/profile/orders`, v2 `POST /v2/order` fallback) in chunks of 10. **Clear all** resets the scanner, and the saved inventory has its own Clear all.
- **My listings (`/inventory/listings`):** everything you have on Warframe Market — sell orders (with the 5 cheapest online sellers and an "undercut" flag, via `src/lib/wfm/reprice.ts`), buy orders and riven auctions — editable here: change a price, hide/show, remove, or bulk reprice (undercut / match / market average, with a floor and optional raise). Uses the v2 orders API (`GET /v2/orders/my`, `PATCH|DELETE /v2/order/{id}`); order creation tries v2 first, then v1. Riven auction edits use the v1 auction endpoints.
- **Arcane prices:** an arcane's price is the **average of the 5 cheapest online rank-0 sell listings** (from the full order list, `/v2/orders/item/{slug}` — the `/top` endpoint is NOT a cheapest-5 list), with the cheapest listing shown beside it and the last 48 hours' sales volume from the statistics endpoint. If there aren't 5 rank-0 listings, it's the **cheapest online max-rank listing ÷ the copies a max-rank arcane is made of** (21 for rank 5, 10 for rank 3: ranks 0…5 take 1, 3, 6, 10, 15, 21 copies) — see `src/lib/arcanes/effective-price.ts`. With no max-rank listing either, the few rank-0 listings are shown flagged "thin". Only online sellers count. These are asking prices, not sales.
- **Vosfor collections:** each of Loid's 9 collections costs 200 Vosfor + 50,000 credits for 3 arcanes. The page ranks them by the plain average price of the arcanes in the collection, and also shows an odds-weighted figure (rarity chances × the average price within each rarity) — the closest thing to "platinum per pack".
- **Primes:** the Prime parts page ranks parts and sets by price (average of the 5 cheapest online listings) with ducats and vault status; the Best relics page values each relic as the expected platinum from one reward pick at each refinement (odds × price; Forma counts as 0). A part is "vaulted" only if every relic that drops it is.
- **Weapon ranking:** Warframe Market publishes no riven sales data, so weapons are ranked by the median *asking* price of their cheapest buy-it-now rivens (up to 99 per weapon). For popular weapons that describes the low end of the market. "Stats that ask more" compares listings with and without a stat in that same sample.
- **Live:** `/live` shows the world state (cycles, fissures, Baro, sortie, archon hunt, Teshin, Darvo, Nightwave, invasions) from api.warframestat.us, cached for a minute per server instance.
- **Rate limiting:** one shared 350 ms throttle per server instance + a 12-minute cache (memory + `market_cache` table, stale-on-error). The throttle is per lambda; the shared cache is what keeps combined volume low.
- **Grading:** per stat, from browse.wf's Riven Calculator at a fixed 1.2 disposition: a ±10% roll around each stat's center, 11 bands (S … F). **Curses are different:** a curse's grade is a fixed rating for the stat (and weapon) from `data/curse-ratings.json`, not its roll — the gauge and band table still show where the roll sits, as information. A curse with no rating falls back to roll grading (a milder penalty grades higher, as on the calculator), and says so. Stats browse.wf doesn't list (combined elements, weak point stats, Zoom on shotguns …) are graded from the Unified-Codex calculator's ranges instead, and the result says so; they have no 1+/1- layout. 
- **Rank scaling:** riven stats scale with rank ((rank+1)/9). All comparisons and grading are normalised to rank 8.
- **WFM tokens:** passwords are never stored; the session token is AES-256-GCM encrypted (user id as AAD) in a table no client role can read.
- **Not verified live:** the WFM sign-in *success* path and listing creation (need a real account), and screenshot scanning (needs an API key). Request shapes were checked against the real API using fake credentials.
- Riven ranges vary with weapon type and the number of bonus/curse stats; `data/rivencalc.json` has every combination at the fixed 1.2× disposition (see "Grading" below).

Scripts: `npm test`, `npm run typecheck`, `npm run price-check -- soma "Crita-cron" critical_chance=150 …` (live market lookup).
